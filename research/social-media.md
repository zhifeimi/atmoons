## Brand Personality & Visual Style

Brand vibe: friendly, community-first, unpretentious neighbourhood café.

- Logo: "ARIEL'S" in an elegant white serif (Trajan-style capitals) with "EST 2015" beneath; the Dapto sub-brand adds "DAPTO"/"Dapto" in gold (block caps on the FB avatar, handwritten script on the Bopple/IG avatar). Navy + gold + white is the core palette.
- Kiosk design (Dapto Mall): deep navy counter panels with brushed-gold rectangular trim, white marble-look counter tops, light timber slat column, circular navy "ARIEL'S EST 2015" blade sign, red feature wall with white coffee-cup icon wallpaper. Brass/gold A-frame sign holders. See maps-kiosk-interior.jpg / mall-kiosk.jpg.
- Photography: bright, close-up phone-style food shots; navy branded paper/plates ("ARIEL'S EST 2015") used as plating surfaces; latte art featured often; flat-lay spreads for the cover photo. No heavy filtering — natural, warm, casual.
- Colour palette of the feed: navy blue + gold/amber + warm food tones (browns, reds of bacon/pizza), white marble, red feature wall. Emoji used liberally in captions (☕🍳🥤🌯🍔👻💀).
- Tone of voice: warm, direct, exclamation-friendly, community-oriented ("see you soon!", "made with love", "Thanks to everyone who joined in the fun!"). Promotional captions announce daily specials and events (pizza day, free coffee for mums with prams every 2nd Tuesday, holiday hours, Halloween costumes).
- Coffee credentials: Campos Coffee (signage "PROUDLY SERVING Campos", bean retail display — Dark City, Roma, Blade Runner, Indonesia, Superior, King St blends, 250g bags, "ANY 2 BLENDS FOR $" offer, La Marzocco machine visible); Bondi Chai served; keep-cup program visible.

## Failed Attempts

1. `curl` on https://www.instagram.com/arielsdapto/ (desktop UA): returned the generic login wall (630KB HTML, no og:image/profile data). Instagram blocks unauthenticated HTML scraping.
2. `curl` on https://www.facebook.com/ArielsDapto/ (desktop UA): returned a 1.5KB Facebook "Error" page (blocked). Worked around via m.facebook.com (mobile UA) which served og:image + follower meta, and later via real browser.
3. WebSearch tool: broken in this session (API 400 errors) — used Bing HTML scraping and live browser instead.
4. Instagram viewer mirrors (imginn.com, imgsed.com, picuki.com, dumpor.com): all Cloudflare-challenged or empty. imginn/imgsed/picuki unusable.
5. maps.app.goo.gl short link: resolves via JS (content-length 0, no Location header); worked around by opening the place page already in the browser.
6. Bopple API probes (api.bopple.me/api/venues/10354, etc.): empty/404 — the menu item photos load via authenticated JS calls; only static venue assets were harvestable.
7. Two Facebook CDN images (media 481209367_609743585155483 and 481656517_609087801887728, s851x315 cover crops): "URL signature mismatch" on re-download (oh param rotation); both were small crops (<20KB) and were deleted. The remaining FB crop fb-post-2025-02a.jpg (25KB) was kept.
8. IG post page media is login-gated for full resolution; only 640px og:image/grid versions were obtainable (fine for web use).
9. googleusercontent Maps photos: the photo viewer only lazy-loaded 3 photos in a logged-out session (arrow navigation and synthetic keyboard events did not advance it); 80+ photos exist but require interaction/login.
10. bopple-venue-header.webp was byte-identical to bopple-venue-card.webp (same asset) — deduplicated. fb-post-2025-02c.jpg (15KB) and the two <20KB FB crops were deleted per the >20KB rule.
